优先解决开始/继续训练、动作搜索、填写重量与次数、保存饮食时的延迟；同时检查启动、回前台、滚动和媒体页面内存。保留现有记录、备份格式、业务规则和全部功能。

本实施轮已获准做性能改动，独立分支、独立 PR；不夹带导航或翻译改造，不自动合并、覆盖真机安装包或发布。测试安装前先保存当前记录并核对可恢复的本地备份。

## 4. 优化前后测量设计

### 固定实验条件

- 主验收使用上述同一部 iPhone，固定 iOS、语言、字体、屏幕刷新/低电量设置、充电状态和健康连接状态；记录温度/thermal state，过热后先冷却。不要把 60 Hz 与 120 Hz 的帧预算混算。
- 数据 A：用户当次记录的经确认本地快照；记录训练/组/饮食/模板数量、时间跨度和只在本机保存的校验值。数据 B：空库，验证首次使用。数据 C：可重复生成的较大历史集，验证增长趋势，不伪装成用户真实数据。
- 正式 A/B 使用一致起始快照和一致操作序列。测试会写入的训练/饮食使用明确的测试副本；不要为反复测试覆盖用户当前库。导出备份不等于健康授权/导入缓存也已备份，健康连接状态要另行记录。
- Release 用于构建配置，Product → Profile 为运行入口；保留符号以便定位。将未附加调试器的体验测量与 Instruments 归因采样分别记录，不把工具开销混入收益。
- 冷启动指进程不在内存的启动；单独标记首次安装、首次建库和系统重启后的冷缓存，不卸载 App 来模拟每次冷启动。

### 必测场景

| 场景 | 固定动作 | 指标和次数 |
| --- | --- | --- |
| 冷启动 | 从桌面打开，到首页主按钮能响应；再测打开动作选择器 | 至少 10 次；逐次值、中位数、最慢值；首帧时间与可交互时间分开 |
| 页面切换 | 今日→训练→饮食→趋势→恢复→今日；含已有进行中训练 | 至少 20 轮；交互响应、主线程占用、hitch 数量/时长 |
| 回前台 | 已有训练输入状态下，后台 30 秒后回来；另做较长后台观察 | 至少 10 次；恢复可交互时间、刷新次数、草稿/已保存记录一致性 |
| 搜索动作 | 输入、删改、清空“卧推 / bench / 哑铃 / dumbbell”；中文拼音组合输入；同时改变筛选 | 至少 30 组固定查询；按键回显与结果更新分开，统计 p50/p95、过期结果次数 |
| 重量/次数 | 连续输入 `62.5`、`12`，清空重填、快速切换字段、加减重量、完成一组 | 至少 30 组；逐字符回显、最终文本/数值读回、save 次数与磁盘落盘结果 |
| 保存饮食 | 输入一餐、改份量、保存、重开；再测最近食物/固定餐 | 至少 20 次；按钮反馈与持久化完成时长，防重条目和汇总一致性 |
| 滚动 | 固定速度滚动动作列表、训练历史、长训练、饮食和报告 | 每条至少 3 段 30 秒；Hitches 时间线及具体调用栈，不只报平均 FPS |
| 媒体与内存 | 动作详情视频、二维人体图和 3D 分别反复进入/离开、切 Tab、回后台 | 每类 30 轮；第 1/5/10/20/30 轮回到同页并静置 10 秒的 footprint、存活实例数 |

使用 App Launch、Time Profiler、SwiftUI/Hangs/Hitches、Allocations/Leaks；数据库和资源读取必要时补 File Activity。分段录制，避免把所有工具同时开启后得到难解释的数字。每组公布样本数与逐次值，小样本 p95 只用于这组对比，不能外推成所有用户的总体分布。标记仅记录事件、时长、计数，不记录食物名称、备注、健康值或新增遥测。

### 候选验收门槛

以下是本项目建议目标，**不是本次测量结果，也不是对所有设备的保证**。在优化前冻结口径，不能看完结果再降低标准。

- 输入、按钮按下反馈 p95 ≤ 100 ms；固定输入脚本中丢字、重复字、错写到其他组、焦点无故跳动均为 0。
- 搜索结果自最后输入起 p95 ≤ 200 ms，含可选防抖；旧请求覆盖新请求为 0。
- 已有内容的 Tab 切换/回前台首个可操作界面 p95 ≤ 200 ms；冷启动先记录上述样本中位数/最慢值，目标中位数 ≤ 1 秒、最慢 ≤ 2 秒。未达标须解释 trace 中剩余耗时，不用更快首帧掩盖不可点击。
- 饮食保存与完成一组的按钮反馈 ≤ 100 ms；持久化耗时单列，建议 p95 ≤ 300 ms，提交完成前不虚报成功。任何性能收益不能抵消记录丢失。
- 固定 30 秒滚动段没有肉眼可感的停顿；记录超过帧预算的 hitch 数量与累计时长，优化后不得恶化。150 ms 以上单次卡顿必须逐个归因；帧预算随实际刷新率记录。
- 内存预热后应进入稳定平台；如果后 10 轮稳定点仍高于前 10 轮超过 `max(5 MB, 5%)`，或每轮新增未释放播放器/scene/observer，则必须解释和复验，不能直接通过。允许有界图片缓存，不要求每次返回精确回到启动内存。
- 数据相同、计算版本相同，分析结果与已确认事实一致；安全提示、缺失状态、目标采用和授权撤回行为不退化。

## 5. 实施方案

### A. 动作库与搜索：首要改动

1. 将资源读取、JSON 解码、目录校验和索引准备变成独立后台执行单元。只传值类型、明确 Sendable 的不可变数据；UI 对象仍在 MainActor 上发布状态。不把 `Task {}` 本身当作线程切换，实际用 profiler 验证执行器与主线程时间。
2. 按目录内容/版本一次性生成条目 ID 索引、双语规范化检索文本、部位/器械/肌群筛选集合。保留两种语言的名称与步骤，中文器械别名进入搜索词；不改原始 ID、排序和历史引用。
3. 查询只规范化当前 query，再检索已准备的索引；不要在每条记录、每次字符变化中重新拼接和 folding。结果只提交一次；列表使用稳定 exercise ID。
4. 优先测量无防抖索引版。如果仍需要，将防抖限制为约 100–150 ms；中文输入法组合态不中断输入，清空/取消立即生效。取消旧任务，加查询序号校验，防止已开始但未及时取消的任务回写。
5. 目录加载状态与空结果分开；首页先可用。已有训练、饮食不等待目录；进入选择器时复用同一个加载任务，有错误可重试，不重复开启读盘。
6. 在原有双语搜索测试上补语义等价、组合筛选、空白/大小写/音调、连续改词后仅显示最后结果、加载失败恢复。新测试验证结果和竞态，不绑定某一种索引实现。

### B. 刷新与分析：按真实变化计算

1. 建立单个刷新协调入口，合并启动/前台/页面出现/设置关闭/健康同步触发的在途请求。多个页面订阅同一结果，不能各读一遍数据库。
2. 把“数据变更”与“时间推移”分开：保存成功、导入/删除、目标变化、健康样本/授权状态变化触发对应数据 revision；跨日、时区变化、恢复随时间衰减及有效期到点也触发重算。不能只比较数据库内容就永久缓存恢复分数。
3. 缓存键包含事实 revision、分析窗口、时区、计算版本、必要时间片、目标/校准/健康授权状态；显示翻译由双语计划独立处理。避免为了判断是否变更，又全量序列化/hash 全库。
4. SwiftData 的 ModelContext 和持久化对象不跨 actor 传递。先做有界查询与纯值快照；若仍是瓶颈，再以独立隔离的读取 context/ModelActor 处理已提交数据，明确合并时序。正在输入的未提交编辑不能被后台旧快照覆盖。
5. 查询先按窗口、状态及目标 ID 下推 predicate/sort/limit。历史目标需保留窗口起点之前最近的有效版本，PR/上次表现需保留各自历史语义；不能简单截断所有历史。
6. `yyyy-MM-dd` 内部日期键仍用 Gregorian、POSIX 和明确时区；复用 formatter 必须受 actor/线程隔离，或使用可安全复用的格式化值。预计算窗口边界和同批日期，不能因界面语言改变内部键。
7. 已显示内容保留，后台更新不挡训练/饮食；错误只影响对应分析卡。可短暂显示旧的分析摘要，但应有简短过期状态，且**不能拿旧缓存采用目标、开始建议训练或发送 AI 请求**；这些动作继续复核当前事实与授权。
8. 回归缓存失效：编辑/删除旧记录、备份导入、午夜/时区切换、健康断开/撤回、目标撤销、计算版本变化、离线失败后恢复。

### C. 保存与输入：先保可靠性，再减少写入

1. 测出 save 实际耗时和每次操作的调用次数。先去除完整训练字符串 fingerprint 的重复构造、无变化保存和重复通知；避免每个字符使整个训练/历史页面重算。
2. 文本输入保留原始编辑态，允许 `""`、`"62."`、中文组合输入等中间状态；解析与字段提交分开，切换语言或刷新不能格式化覆盖光标下的文本。
3. 将单次用户事务中的多字段修改合并为一次可靠保存，例如沿用参数、增加组、完成组及休息时间更新。**完成一组、增删动作/组、退出编辑、结束训练、进入 inactive/background** 都必须处理未提交值并立即 flush；成功后才显示已保存/离开。
4. 连续编辑的延迟保存只适用于已被可靠草稿机制覆盖的非关键中间更新，可先评估 200–300 ms 的有界合并。系统强杀/崩溃不保证调用 `onDisappear` 或后台回调；仅加防抖和生命周期 flush 不足以宣称不丢数据。
5. 因当前未发现持久化草稿日志，**首个性能 PR 默认不放宽记录持久化保障**。若 trace 证明必须延迟实际记录写入，先单独评估小型可恢复草稿/日志成本；恢复验证通过前保留即时保存，不为满足优化清单而强行引入更大的数据层重构。
6. 失败保留输入和脏状态，可重试；不要用全局 rollback 清掉其他页面尚未提交的数据。取消历史编辑继续不写回；训练完成失败恢复进行中状态。
7. 真机验证连续编辑后切 Tab、锁屏、后台、重启，以及测试副本的强制终止恢复；校验每组重量/次数/RIR、顺序、完成状态、餐次和营养值。不用“看见 UI 更新”代替重新读库。

### D. 3D、图片和视频：基于生命周期验证

- 保留按需创建 3D、无连续渲染及已有 teardown；测试切 Tab 后视图未销毁的情况，区分页面可见性与 App active 状态。不可见时停止播放/绘制，必要时拆除重资源；保留用户选择用于返回恢复。
- 海报与二维图按实际显示尺寸解码/下采样，移出 `body` 的磁盘读取；有界缓存使用资源 ID/尺寸/scale，不按每次视图值重复读取。两张人体 PNG 各约 1.18 MB，仅为压缩大小，实际内存另测。
- 视频异步加载后提交前检查当前资源、页面和取消代次；离开后撤销 KVO、超时任务、looper、playerItem 和 layer 关联。现有清理逻辑先验证，不无依据重写。
