# P1：第一次使用更直观与说明文字收纳计划

状态：**计划中，待用户审阅；没有修改界面或执行真实记录操作。**

日期：2026-10-12（Europe/London）。代码基线：`c970330a33208b9f7862ae6e960d5f5b98a17a1f`。关联：[性能计划](device-performance-plan.md)、[双语计划](localization-plan.md)。

## 1. 核心目标

第一次打开就能找到三件事：开始/继续训练、给训练加动作并记录一组、记录一餐。首页两次点击以内开始或继续训练；记餐与历史入口清楚；不先要求创建模板、完整身体资料、开健康权限或理解恢复指标。

用户的补充要求作为明确设计约束：**能省的免责声明、解释性小字直接省；需要保留的通用方法、边界、隐私、来源和术语说明集中到一个离线页面，正常页面不反复铺开。**不能通过在每页新增一段更短的小字来代替收纳。

本计划保留现有五 Tab 的所有能力：训练模板、历史/PR、饮食库/固定餐、趋势/目标、恢复/体感、二维/3D、报告/历史、健康连接、备份等。调整入口和层级，不删除功能、不改算法、不改数据。

## 2. 当前三条流程：代码路径与疑点

以下是**代码走查，不是真机或新用户实测**。本次已确认设备与安装版本，但还没实际完成三条流程；不能把下列推断写成已观察到的用户失败。正式调整前按第 3 节补一次现状走查。

| 流程 | 当前路径（进入首页后计数） | 已有优点 | 推测的困惑点 |
| --- | --- | --- | --- |
| 新训练 | 今日“开始训练”→“空白训练”或模板→进行中 | 无模板也可开始，代码路径为 2 次点击 | 主动作与饮食同样强调；首次引导/建议又先让人建模板，容易误会成前置条件 |
| 继续训练 | 今日“继续训练”→正在进行的训练 | 代码路径为 1 次点击；开始意图已有消费/复用保护 | 训练页右上开始按钮在有进行中训练时禁用，需要实测是否明显能从进行中卡进入 |
| 添加动作并记录一组 | 进行中→添加动作→搜索/筛选→选动作→填写重量/次数→点组左侧圆圈→页面右上“完成”结束整场 | 搜索双语、已有默认记录方式与一组；已有重启保存和历史编辑逻辑 | “第 N 组”的圆圈按钮不直接说“完成本组”；RIR、组类型和说明在核心输入前；空白训练首先看到名称/休息设置 |
| 记录一餐 | 今日“记录饮食”→五种来源选项→“直接记录”→表单→保存 | 最近、常用、固定餐、复制都有；保存前有总量 | 新用户没有可复用内容，却必须先选来源；表单含两套营养数值、基准、份量、多段 footer，主次难分 |

## 3. 修改前的实际走查

1. 使用已经核对身份的测试包；记录是手机当前包还是已知源码的独立测试构建，不能混为同一版本。
2. 在独立空库走首次安装三流程；在经确认的测试副本走已有进行中训练、有模板/历史/食物的回访流程。用户手机现有记录仅做不改数据的观察；需要创建测试训练/食物时先隔离数据。
3. 保存截图/录像和逐步记录：看到的主要按钮、实际点击次数、停顿/误点/返回、键盘遮挡、是否需要口头解释。点击数从可交互首页计；首次引导/跳过额外计一次，不能藏在统计外。
4. 先按用户的自然选择完成，再按既定路径复核。注明“开发者走查”与“首次使用者独立完成”的证据差异。
5. 三条现状流程与拟议流程各一份对照；现状能在两次内开始训练就明确保留这个优点，不为优化点击数改坏恢复进行中训练的逻辑。

走查未完成时可继续画界面方案，但体验问题只标为假设。交互 PR 开始前应补齐此基线。

## 4. 今日页界面方案

### 推荐信息顺序

1. 简洁日期和设置入口。
2. **一个最明显的主按钮：开始训练 / 继续训练。**有进行中训练时附训练名与进度等业务信息。
3. 清楚的次按钮“记录饮食”，保留易点的面积，降低视觉权重。
4. “今天已记录”：训练状态、餐次/营养的简短摘要；点摘要进入对应历史/当天明细。
5. 有模板时可出现最近模板捷径；不要求模板先配置。完整模板库仍在训练入口。
6. 进展相关功能通过清晰导航访问，首页不同时摆恢复大卡、周报大卡、报告历史大卡。将重复的入口和宣传/解释文字撤下，功能仍在对应页面。

文字线框仅表示层级，不是已实现界面：

```text
今日                                  设置
10 月 12 日

┌──────────────────────────────────────┐
│          开始训练 / 继续训练          │  主按钮
└──────────────────────────────────────┘
                 记录饮食                 次按钮

今天已记录
训练：进行中 / 已完成 / 尚未记录       →
饮食：今天的记录与合计                →

最近模板（有内容才出现）              →

今日       训练       饮食       趋势       恢复
```

首页的空摘要不再同时用多个大号 ContentUnavailableView 抢占空间。无记录时保留一个清楚下一步，例如“开始第一场训练”的可点击主按钮；无需另外长篇解释功能。新用户默认可直接记录，健康连接和资料完善只在主动打开相关功能时出现。

## 5. 五 Tab 与四 Tab 的取舍

| 方案 | 结构 | 优点 | 代价 |
| --- | --- | --- | --- |
| A：保留五 Tab，收敛首页（**首个改动推荐**） | 今日 / 训练 / 饮食 / 趋势 / 恢复 | 趋势和恢复保持一步直达；变更小，现有用户不需要重学；能独立解决首页拥挤 | 导航项较多，趋势/恢复属于“了解进展”的关联不够集中 |
| B：四 Tab，统一进展 | 今日 / 训练 / 饮食 / 进展；进展内“趋势 / 恢复”，周报/报告作为明确入口 | 功能归类一致，未来扩展有位置 | 从任意页面到非当前分析分区要多点一次；周报/报告移动后需重新建立位置记忆 |

### B 方案的可用性边界

- 进展直接打开上次使用的趋势/恢复分区，顶部可见分区切换；不先新增一层菜单页。首次默认趋势概览。
- 前往上次分区为 1 次点击，另一分区为 2 次；原五 Tab 两者都是 1 次。**记住上次分区不等于所有路径都没有新增步骤。**
- 训练历史始终在训练，饮食历史始终在饮食，不塞进“进展”；这两条高频路径不增加步骤。
- 周报与报告历史有文字入口，不藏在不明含义的图标里；入口移动应在现状/方案任务测试中比较。

建议先实施 A 的首页与流程收敛。B 作为可比较的导航草案；若实际走查表明用户更易找到趋势/恢复，且接受偶尔多一步，再单独确认采用。不在首个交互改动里顺手合并 Tab。

方案 A 中，趋势页统一安放“每周回顾与 PR”“报告与历史”的低层级入口，必要时训练历史保留周报捷径；恢复仍从原 Tab 进入。将入口下移必须保持全部原功能可达，并检查页面内操作数。

## 6. 三条主流程的具体调整

### 开始 / 继续训练

- 无进行中训练：今日→开始训练→“直接开始”或既有模板，保留 ≤2 次点击。将“空白训练”改为更能说明动作的“直接开始”；有模板时沿用模板选择，取消后不产生空记录。
- 已有进行中训练：今日→继续训练，1 次点击回原 workoutID、当前内容与计时；不得新建副本。
- 空白训练进入后，最突出“添加动作”；训练名/备注及休息设置收纳到较低层级，保留默认可用值。
- 刚完成训练返回时不再弹出新的开始页；保持现有意图消费回归测试。
- 训练页空状态内直接给“开始训练”按钮；模板为可选入口，历史明确按日期显示。

### 添加动作 / 记录一组

- “添加动作”可见且有文字；选择器直接提供搜索和筛选。选择动作后回到新增动作及其第一组，键盘和焦点落在合理位置。
- 每组先看到“重量 / 次数 / 完成本组”；时长或有氧使用相应核心字段。确认图标有可理解状态和辅助功能名称，区分“完成本组”与整场“结束训练”。
- 组类型、RIR、备注可放入每组/动作的可展开“更多”区域；不改变默认组类型，也不默认把缺失 RIR 填为 0。展开/收起保留值。
- 将“保留次数 RIR”呈现为“还能做几次（RIR）”等短标签；完整解释在统一说明页：如“这一组结束时，估计还能完成的次数；可以不填”。不每组重复显示解释段落。
- 完成组后显示已完成状态，按原设置启动休息；输入/保存错误靠近相关字段或以明确错误反馈出现，不被说明收纳隐藏。
- “增加一组”保留并复用合理参数；历史沿用仍明确区分参数与本次已完成结果，有氧仍要求确认本次完成，不能因精简文案取消数据真实性保护。

### 记录一餐

- 今日“记录饮食”直接进入一个记录页面；新用户默认空白食物表单，不先选没有内容的最近/常用/固定餐。
- 表单上方或工具区保留“最近 / 常用 / 固定餐 / 复制一餐”的次入口，已输入草稿在来回选择时不被静默丢弃。来源面板取消后回到原草稿。
- 首屏强调食物名、实际份量/基准、餐次；营养输入保留在主表单，计算后的总量用一个清楚摘要展示。需要手动修正总量时通过明确的“修改总量”进入，不默认并排堆两套可编辑数值。
- 不改变本次合并版本已有的营养换算规则；每份/每 100g 切换、份量缩放、手动修正、旧热量保存都要复测。
- 保存为常用食物是可选开关；先记下当前这一餐，再决定要不要复用。不要求预建食物库或营养目标。
- “保存”固定可找到，键盘打开时能收起或直接操作；成功回到所选日期并能看到新记录。失败保留草稿并可重试，防止连续点击生成重复记录。
- 全部数据为空/零仍按现有校验处理，“尚未填写”与“真实零摄入”不能合并；日期、餐次、缺失营养是业务信息，应保留。

## 7. 统一“帮助与说明”页面

### 单一入口与结构

设置→**帮助与说明**为常驻入口，扩展已有 HealthHelpView，避免再造一套平行文档。页面离线可读，提供顶部目录和锚点，说明可折叠但都在同一页面内。

建议内容顺序：

1. 快速开始与术语（RIR、工作组/热身组、恢复指数）。
2. 饮食计算与完整记录（每份/每 100g、热量估算、份量/总量关系）。
3. 趋势与恢复的计算方式、适用范围和缺失数据含义。
4. Apple 健康、权限、数据处理、撤回与删除。
5. AI 报告的状态、第三方处理选择和历史依据。
6. 本地保存、备份/恢复和兼容范围。
7. 动作/图片/视频/3D 来源、必要许可全文、反馈方式。

日常页面不再插入整段“仅供参考”“工程初值”“此页面如何计算”等通用说明，也不强制每页加常驻 `?` 小字。确有需要的上下文帮助由工具栏菜单或明确的“查看依据”进入**同一个页面的相应位置**，返回后仍保留原上下文。

### 当前文字的处理清单

| 当前内容 / 位置 | 处理 | 保留在哪里 |
| --- | --- | --- |
| 今日口号、卡片重复副标题、先建模板提示 | 删除重复内容；用明确按钮代替 | 无需迁移宣传性文字 |
| 每组 RIR 解释 | 正常组行移除；短标签表达问题 | 术语锚点 |
| 饮食公式说明、基准/总量缩放 footer、保存前预览承诺 | 删除重复承诺；规则合并 | 饮食计算锚点；实际数值/单位仍在表单 |
| 饮食页“趋势只计昨天前 14 天”、趋势图长脚注 | 从记录流程移除；指标名称/单位/未知状态保留 | 趋势方法锚点；图例必要语义用简洁图例表达 |
| 恢复算法版本、工程阈值、模型局限 | 正常摘要不常驻长说明 | 恢复方法/诊断详情；指标可称“恢复估计”，避免必须靠脚注纠正误导 |
| 报告卡长边界说明、未开放功能的重复说明 | 只保留当前可行动状态，如“本地报告”/“暂不可用” | 报告/AI 说明锚点；历史、过期和缺失状态保留 |
| 每个动作底部来源说明、视频 attribution | 集中到对应资源来源/许可区，保留可追溯关联 | 帮助与说明的来源区；具体授权若要求可见署名，再用最小对应入口，逐项核查 |
| 无视频动作“尚未收录动态演示” | 直接展示动作步骤，不留空媒体区占位解释 | 无需作为常驻说明；主动播放失败仍给反馈 |
| 设置权限路径、备份版本长段落、关于/支持重复正文 | 合并，常规设置只保留操作/状态 | 权限/备份/来源锚点 |

### 不应被误删的操作信息

“少小字”不等于删除具体操作的结果或风险。以下继续在需要时出现，但不铺在每一页：

- 当前字段校验、保存失败、未保存草稿、加载失败和重试。
- 用户主动删除/放弃记录前的明确确认；包含会删除什么，不用模糊“确定吗”。
- 进入第三方数据处理前的明确选择，继续独立于健康权限。可从设置进入统一说明页的 AI 段落，在该模式下提供“同意并启用”按钮；不能因为说明集中而默认同意或只剩一个普通开关。
- 疼痛/活动受限、数据未知、结果过期等与当前事实有关的状态；通用算法局限集中，具体风险状态不隐去。
- 系统 HealthKit 授权弹窗、实际单位、营养值、记录时间与有效期属于必要交互/内容，不属于要删掉的免责声明。

说明页内容去重与表述修订同步双语，保留离线可访问性。必要许可、原始资料和报告依据仍完整保存；不因视觉收敛删除资源归属或证据。

## 8. 按钮、键盘、返回与辅助功能

| 项目 | 统一规则 |
| --- | --- |
| 主按钮 | 每个主要步骤只有一个明显的下一步；今日“开始/继续训练”、组内“完成本组”、表单“保存”、整场“结束训练” |
| 次按钮 | 记录饮食、添加动作、增加一组、模板/复用入口保持可读和易点；视觉层级依场景决定，不一律用浅灰 |
| 返回/取消 | 返回保留进行中训练；编辑草稿按原语义取消；有未保存内容时给继续编辑/放弃选项，不能弹多层确认 |
| 键盘 | 数字键盘有“收起键盘”，避免与“保存/结束训练”同名“完成”混淆；焦点跳转合理，关键输入和操作不被遮挡 |
| 点击区 | 关键按钮与图标至少 44×44 pt；完成组、加减重量、删除、返回逐项检查，不能只靠视觉尺寸 |
| 大字号 | 表单核心输入改纵向，支持多行；主要按钮与 Tab 文字不截断/重叠，不强制缩小字体 |
| 暗色 | 语义颜色、足够对比；成功/警告/未知不能只靠红绿区分 |
| VoiceOver | 读出字段、单位、组序号和完成状态；历史/过期/缺失明确；装饰图不重复朗读 |

| U5 | 独立交互 PR 与任务测试结果 | 不自动合并或发布；列出未验证部分 |

首个交互改动使用 A（五 Tab）作为建议边界；四 Tab 要有单独的选择与任务测试，不与 U2 捆绑。U2/U3 仍可分小提交审查，不借此重写所有 View 或数据模型。

### 验收任务

1. 新用户不填资料、不授权健康、不建模板：从首页 ≤2 次点击进入训练；已有进行中训练 1 次点击继续同一记录。
2. 无人提示找到添加动作，能搜索“卧推 / bench”、添加动作、输入一组并标记完成，区分完成一组和结束整场；重开历史数值一致。
3. 无预设食物也能找到记录一餐；已使用用户仍能找到最近、常用、固定餐和复制；保存后在正确日期看见记录，无重复。
4. 首次使用者能独立找到训练历史、饮食历史；能解释下一步按钮会做什么。条件允许时由 3 位未使用过 App 的人各走三任务，记录成功、误点和求助；无此条件则如实记“仅开发者/用户走查”，不替代新用户验证。
5. 正常今日、记录训练、记录饮食页面没有通用免责声明/方法小字；设置一次进入“帮助与说明”能找到全部保留内容。缺失/错误/破坏性确认仍可见。
6. 选择语言、切 Tab、回后台和取消面板不丢正在写的重量/次数/餐单；性能沿用 P0 验收，不能为了少一个页面引入重复保存或加载。
7. 中英 × 明暗色 × 默认/最大辅助字号；检查键盘、点击区、VoiceOver、Reduce Motion，以及二维/3D/视频返回路径。
8. 功能保全清单逐项勾选：空白/模板/继续训练、组与 RIR、有氧、历史编辑/再次训练/PR、饮食五来源、目标历史、趋势、恢复/体感、报告/依据/历史、资料库、健康连接/撤回、备份恢复。

扩展现有 `DailyUseUpgradeUITests`、`HealthIntegrationUITests`、`TrainoteUITests`、营养/目标草稿测试。采用稳定 identifier 与数据回读，不让测试只断言按钮新标题存在。

## 10. 风险、回滚与本次未验证项

- 调整 sheet/NavigationStack 可能丢草稿、重复创建训练；控制 UI 身份，保留已有修复与数据安全回归。
- 将复用功能收进次入口后可能更难找；用回访用户任务验证，不能只看空库截图。
- 精简解释可能误删实际状态；按第 7 节清单逐项确认，不进行全局删除 `.footnote` 或 `.caption`。
- 回滚按首页层级、流程入口、说明收纳三个独立提交进行，保持数据库不变；原入口映射在 PR 中记录以便恢复。
- 当前只完成代码路径与方案，未完成三流程真机实际走查、新用户测试、可点击原型、排版/辅助功能及数据回读。本文件线框是设计提议，不是运行界面截图。
- 本轮不采用新视觉品牌、重新配色或大量动画；使用现有原生组件，通过层级、文案、顺序与状态减少理解成本。
