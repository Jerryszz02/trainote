# Trainote 日常使用与可靠性升级

## 目标与交付边界

在现有离线 iPhone App 上完成训练、饮食、周报与 PR 的完整日常使用闭环。保持无账号、无运行时联网、无遥测；已有历史记录不能因分类或模板更新而改变。真机、签名、TestFlight 与 App Store 发布单独记录，不以模拟器通过代替。

## 实施顺序

1. **数据与动作记录契约**：四种方式（重量×次数、次数、时长、有氧）；按全部 1,324 个动作的名称、器械、说明选择默认方式，支持用户切换。旧 `strength`/`cardio` 数据保持原语义。新字段必须有兼容默认值，并验证旧库升级。
2. **训练效率**：上次完成数据对照、一键沿用、组间休息计时、快捷加减、历史编辑与再次训练；模板编辑使用草稿，保存成功才关闭。切换方式不能默默删除已填写数据。
3. **饮食效率**：最近食物与搜索、重复一餐、份量自动换算、每 100g/每份录入、固定餐应用前调整。历史编辑保留原时间；从今日进入始终落在今天。
4. **反馈与首页**：本周概览、历史周切换、同动作重量 PR 与单次容量 PR、记录完整度说明；首页继续训练、常用模板和可跳过入门引导。
5. **可靠性**：所有保存失败有可重试反馈；完成前校验全部有效记录；进行中修改及时保存；备份导出/恢复、升级兼容、应用内离线隐私与帮助；大数值、跨日、误操作和重启恢复。
6. **验收与交付**：单元与 UI 测试、完整模拟用户流程、浅深色与大字号截图检查、修复本轮发现的缺陷。审阅 diff 后提交、推送并创建 ready PR。

## 关键产品规则

- 默认记录方式是便利功能，用户可以切换；界面只显示当前方式需要的字段。
- 杠铃、哑铃等负重动作优先重量×次数；动态自重动作优先次数；静态保持与拉伸优先时长；持续有氧保留时间、距离与可选热量。
- 上次成绩只来自已完成训练中同动作、同记录方式的有效完成记录。预填后所有组仍未完成。
- PR 只比较同动作、同记录方式、严格早于本次的已完成训练。首次记录是基线；平纪录不算新 PR。容量是该动作本次有效完成组的重量×次数总和，不用自重 0kg 伪造容量。
- 周报以周一为起点，按已完成训练的开始日期归周；没有饮食记录的日期显示未记录，不作为零摄入日参与平均。
- 改份量按原营养密度等比例换算，重复记录生成独立快照；更改模板不会改写历史。
- 保存成功才显示成功或退出。模板取消不写入，历史训练编辑需显式保存。
- 恢复备份必须先验证完整格式、版本和全部数值，再进行原子导入；不自动清空现有数据。

## 验收场景

- 首次打开 → 建立模板 → 开始训练 → 负重/次数/时长/有氧各完成记录 → 休息计时 → 完成并查看历史。
- 第二次同动作 → 看到上次数据 → 沿用并增加重量 → 完成 → 看到正确的 PR；平纪录、未完成组不触发。
- 编辑历史后取消/保存均符合预期；训练中切后台与终止重启仍可继续。
- 保存每 100g 食物 → 记录实际克重 → 改份量 → 再次记录/复制一餐 → 汇总正确。
- 查看昨天后从今日记录不会落到昨天；修改历史备注/名称不改变原记录时间。
- 周报跨日跨周正确，漏记不会被当成零摄入。
- 旧数据库打开并升级；导出、验证、导入和重复导入保护；损坏备份不改变已有数据。
- 真机/签名/上架未验证项保留明确清单，不能宣称完成。
